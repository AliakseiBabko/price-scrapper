## Durable, Broadly-Reusable Smeta-Literacy Rules (Level 1, Delivery-Model-Agnostic)

- **Price water/heating rough-in by fixture "points" (a sink needs 2 points: hot + cold), not by linear meters of pipe** — pricing by pipe-length metrics is flagged as a common upsell vector ("turns out we needed more pipe, please pay more"); knowing the fixture count from a design project lets a buyer independently verify this line item.
- **Price electrical rough-in by floor area, not by cable length**, for the same anti-upsell reason.
- **A proper putty/skim-coat job for paint-ready walls has up to ~9-10 distinct sub-steps** (primer → base putty → sand → primer → fiberglass mesh → primer → finish putty → sand → primer/paint) — a smeta line that just says "wall putty" with no sub-step breakdown makes it impossible to verify what was actually done or catch missing steps after the fact. Demand an itemized smeta specifically for this stage.
- **Verify the smeta specifies flooring installation pattern** (straight vs. diagonal vs. herringbone) before work starts — pattern materially affects labor cost and is a common source of "we assumed straight, now pay extra for herringbone" disputes.
- **Verify the smeta specifies plaster/putty quality grade** (simple/improved/high-quality) — each grade has different flatness/tolerance standards, and a design project targeting mid/premium finish quality should specify the high-quality grade explicitly, not leave it implicit.
- **Watch for common corridor/lobby ("МОП"/входная группа) protective-covering requirements** some residential complexes impose on renovation crews — building-management-driven, cost varies by building, easy to miss when budgeting from a generic smeta template.
- **Watch for scope items commonly added mid-project rather than itemized upfront**: reinforcement/opening framing in partition-wall work, corner-bead/priming/window-reveal work in plastering, ancillary cutting/mitering work in tiling — verify these appear as explicit line items in the original smeta, not left to surface later.
- **A substantial contingency buffer is standard practice even in a professional company's own smeta**: this source adds roughly +26% of its own subtotal (~1,000,000 RUB on a ~3.87M RUB base) explicitly for "indirect/unaccounted work" — **notably higher than this project's guide's existing stated 10–15% buffer recommendation**. Single-source, but worth flagging as a data point suggesting 10–15% may be light for some projects — not treated as a replacement figure, just a comparison point.
